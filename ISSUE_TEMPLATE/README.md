# Issue Template Guide

Use these templates to create issues with a consistent structure and enough context for someone else to act on them quickly.

All templates follow the same format:

- Objective: what needs to happen.
- Acceptance Criteria: how we will know the issue is complete.
- Context: background, links, screenshots, logs, or any other helpful details.

The template itself is the same for every issue type. What changes is the kind of details you provide in each section.

## Task

Use this for a clear piece of work that should be completed.

- Objective: describe the deliverable and expected outcome.
- Acceptance Criteria: list measurable completion checks.
- Context: include references, dependencies, design notes, or blockers.

## Hurdle

Use this for bugs, blockers, unexpected behavior, or something that is failing.

- Objective: explain the problem and the impact.
- Acceptance Criteria: define the expected behavior or fix outcome.
- Context: add reproduction steps, error messages, logs, screenshots, environment details, and any temporary workaround.

## Scope

Use this for ideas, proposals, or suggested improvements for the organization.

- Objective: explain the idea and the problem it solves.
- Acceptance Criteria: describe what success would look like if the idea is accepted.
- Context: include examples, motivation, tradeoffs, or links to related discussions.

## Training

Use this for learning requests, onboarding help, or training-related needs.

- Objective: state the topic or skill to learn.
- Acceptance Criteria: describe what the learner should be able to do after training.
- Context: include current skill level, preferred format, timing, resources, and any constraints.

## Feedback

Use this for general feedback from any member.

- Objective: summarize the feedback clearly.
- Acceptance Criteria: describe the desired change, decision, or response if applicable.
- Context: include examples, impact, comparisons, and whether the feedback is urgent or optional.

## Credentials

Use this for secure management and tracking of access information.

- Objective: explain the access request or credential-related need.
- Acceptance Criteria: describe what access should be granted, updated, rotated, or reviewed.
- Context: include the system name, owner, purpose, urgency, approval path, and any security restrictions.

## Legal

Use this for security, IP, or compliance-related tasks.

- Objective: explain the legal or compliance topic.
- Acceptance Criteria: describe the required review, decision, or action.
- Context: include relevant documents, jurisdiction, deadlines, risks, and involved parties.

## Data

Use this for structured data entry and tracking.

- Objective: explain the data work that needs to happen.
- Acceptance Criteria: define the expected structure, completeness, or output.
- Context: include source data, target format, field definitions, validation rules, examples, volume, and update frequency.

## Writing Good Issues

- Be specific and actionable.
- Include links, screenshots, or examples when they help.
- If something is blocked, explain what is missing.
- If a template has an acceptance criteria section, write it as a checklist whenever possible.
